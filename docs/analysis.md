# 랙 분석 구현 메모

코드: `unity/Assets/Analysis/` (UnityEngine 비의존). 진입점 `RackAnalyzer.Analyze(points, settings)`.
파라미터는 전부 `AnalysisSettings` 에 있고 초기값이다 (실측 후 조정).

## 단계

| 단계 | 구현 | 파일 |
| --- | --- | --- |
| 1 전처리 | 복셀 3cm 평균 + 통계적 이상치 제거 (k=8 최근접 평균거리 > 평균+2.5σ) | Preprocess.cs |
| 2 바닥 | 높이 히스토그램에서 최대의 30% 이상인 가장 낮은 봉우리 → 평면 y=ax+bz+c 피팅(3회 재가중) → 5cm 이하 제거 | Preprocess.cs |
| 3 발자국 | 5cm 격자 투영 → 2칸 팽창 → 8-이웃 연결 영역 → 최소면적 사각형. 랙 후보는 공통 주축으로 맞추고 **빈 랙의 앞·뒤 프레임을 짝지어 합침** | FootprintDetector.cs, RackAnalyzer.cs |
| 4 층 | 높이별 "길이 방향 덮임 비율" 프로파일의 봉우리 (덮임 ≥ 0.4, 주변 대비 돌출 ≥ 0.2) | RackStructureDetector.cs |
| 5 칸 | 길이 위치별 "높이 방향 덮임 비율" 프로파일에 칸 수 n 별 빗살 패턴 상관 (기둥 위치 덮임 − 기둥에서 먼 곳 덮임) | RackStructureDetector.cs |
| 6 규칙성 | 층 간격 중앙값의 정수배로 벌어진 곳에 가려진 층을 추정 삽입, 관측/추정 구분 기록 | RackStructureDetector.cs |
| 7 생성 | 기둥·빔 배치, 신뢰도 낮으면 빨강, 추정 부재는 회색 | Receiver/View/RackSpawner.cs |

물체 박스(M3)는 3단계 발자국을 그대로 박스로 낸다 (`objects`).

## A단계(규격 입력)

`AnalysisSettings.Spec` 에 칸 폭·깊이·층(높이 목록 또는 간격[+첫 높이])을 넣으면:
- 칸: n ∈ {round(L/폭) ± 1} 와 시작 위치를 1cm 간격으로 훑어 기둥 위치 덮임이 가장 큰 배치 (점수가 같은 구간의 가운데).
- 층: 높이 목록이면 그대로, 간격이면 첫 빔 높이를 0~간격 범위에서 훑어 빔 덮임 합이 최대인 값.

## 좌표와 결과 형식 (`result.json`)

- `pose` = **1번 칸 쪽 끝, 앞면 모서리의 바닥 점** (Unity 마커 좌표), `yaw` = 랙 길이 방향(로컬 +Z)의 Unity yaw.
  로컬 +X 가 깊이 방향. `uprightPositions` 는 로컬 Z.
- `levelHeights` 는 빔 중심 높이 (바닥 기준). `levelObserved` / `uprightObserved` 가 false 면 규칙성으로 추정한 것.
- `confidence` = 0.5 × 관측된 기둥 비율 + 0.5 × 관측된 층 비율.
- 이름: 열은 원점에서 가까운 줄부터 (줄 = 랙 길이 방향에 수직한 위치), 줄 안에서는 원점에 가까운 랙부터. 1번 칸은 원점에 가까운 끝.
  **현장 관행에 맞게 확정 필요 (TODO).**

## 현재 정확도 (합성 데이터, `tests/` + AnalysisCli 스윕)

4칸×4층, 칸 1.2m, yaw 0~85°, 시드 5개씩:

| 상자 채움 | 자동(B) 칸×층 정답 | 규격(A) 칸×층 정답 |
| --- | --- | --- |
| 0% | 5/5 | 5/5 |
| 30% | 5/5 | 5/5 |
| 60% | 3/5 (층 1개 누락 2건) | 5/5 |
| 90% | 0/5 (층 누락) | 5/5 |

물류가 많으면 상자 앞면이 모든 높이를 덮어 빔이 묻힌다 → 실전은 A단계로 시작한다는 DEV_PLAN 결정과 일치.
합성 데이터는 모든 면이 고르게 찍힌 이상적인 경우라, 실제 LiDAR(얇은 빔 누락, 한쪽 면만 보임)에서는 M4 에서 다시 잰다.
